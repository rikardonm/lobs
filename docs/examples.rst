Hello, World! Application
-------------------------

A minimal example that creates a simple C++ executable with no external dependencies.

**Project File:** ``examples/cmake-single-app/cmake-single-app.py``

.. literalinclude:: ../../examples/cmake-single-app/cmake-single-app.py
   :language: python
   :caption: Project Definition

**Source Code:** ``src/main.cpp`` (auto-generated)

The example generates the following source file automatically:

.. code-block:: cpp

   // main.cpp - auto-generated by lobs

   #include <iostream>

   int main(int argc, char *argv[])
   {
       (void)(argc);
       (void)(argv);

       std::cout << "Hello from lobs!" << std::endl;
       return 0;
   }


**Export to CMake:**

.. code-block:: bash

   python cmake-single-app.py export cmake

This will generate:

.. code-block:: text

   cmake-single-app/
   └── CMakeLists.txt


**Build and Run:**

.. code-block:: bash

   # Configure the project
   cmake -B build .

   # Build the application
   cmake --build build

   # Run the executable
   ./build/cmake-single-app


Expected Output:

.. code-block:: text

   Hello from lobs!


Configuration Customization
~~~~~~~~~~~~~~~~~~~~~~~~~~~

The example demonstrates how to modify compilation flags after project creation:

.. code-block:: python

   app = lobs.cpp.project.SimpleManagedApplication(
       source_files=[Path(__file__).with_name("src") / "main.cpp"],
   )

   # Enable warnings with dictionary-like access
   app.compilation_flags.w_all = True
   app.compilation_flags["w_extra"] = True  # Equivalent to -Wextra
   app.compilation_flags["w_pedantic"] = True  # Custom flag: -Wpedantic


Library Example
---------------

This example shows how to create a static library with public and private headers.

**Project Structure:**

.. code-block:: bash

   external_package/
   ├── lib_a.py                  # Library definition
   ├── nlohmann_json.py          # External dependency
   └── external_package.py       # Application using the library


Library Definition (*lib_a.py*):

.. literalinclude:: ../../examples/external_package/lib_a.py
   :language: python
   :caption: Library Project

Expected content of *lib_a.py*:

.. code-block:: python

   import lobs

   class LibAPackage(lobs.Package, description="Library A"):
       lib = lobs.cpp.project.SimpleLibrary(
           source_files=[Path(__file__).with_name("src") / "lib_a.c"],
           public_includes=[Path(__file__).with_name("include")],
           cxx_standard=23,
           compilation_flags={
               'w_all': True,
               'w_extra': True,
           }
       )


External Dependency Definition (*nlohmann_json.py*):

.. code-block:: python

   import lobs

   class NlohmannJson(Package):
       """Provides nlohmann/json header-only library."""
       pass


Application Using Both Library and External Dependencies:

.. code-block:: python

   import lobs
   from pathlib import Path

   class ExternalAppExample(lobs.Package):
       app = lobs.cpp.project.SimpleManagedApplication(
           source_files=[Path(__file__).with_name("src") / "main.cpp"],
       )


**Export and Build:**

.. code-block:: bash

   # Export the project
   python external_package.py export cmake

   # Configure, build, run
   cd cmake-build
   cmake . && cmake --build . && ./externalapp


This configuration:

- Builds ``lib_a`` as a static library
- Links it with the application
- Includes nlohmann/json from pip (via dependency resolution)

   :caption: ESP-IDF Application


**Source Code Location:** ``src/main.c``

The project expects a C-based source file for embedded development.

**Export to ESP-IDF Format:**

.. code-block:: bash

   python esp-blinky.py export espidf


**Generated Structure:**

.. code-block:: text

   esp-blinky/
   ├── Component/                # ESP-IDF component structure
   │   ├── CMakeLists.txt        # IDF project config

Key Concepts

Dependency Declaration
~~~~~~~~~~~~~~~~~~~~~~

Dependencies are declared by importing packages that satisfy the requirements. The framework uses Python's type system and ``pip`` to resolve them automatically.

Example dependency usage:

.. code-block:: python

   import lobs

   class Consumer(Package):
       def __init__(self, *args, **kwargs):
           # Declare a dependency on nlohmann-json via pip
           super().__init__(*args, **kwargs)


Resolution Flow

1. **Identify Requirements**: Each package declares what it needs (via type annotations or explicit parameters).

2. **Find Providers**: The resolver searches for installed packages that match those requirements.

3. **Validate Versions**: Using ``annotated_types`` constraints, version compatibility is checked.

4. **Merge Dependencies**: All required sub-projects are collected and organized.


Working with pip
~~~~~~~~~~~~~~~~~

Since dependencies are resolved through Python's package ecosystem:

.. code-block:: bash

   # Install required dependencies first
   python -m pip install nlohmann-json3-snapshot

   # Then run your lobs application
   python external_package.py export cmake


Project Composition Example
---------------------------

This example shows how to compose multiple project entities (libraries and executables) in a single package.

**Complete Example:**

.. code-block:: python

   from pathlib import Path
   import lobs

   class ComposedProject(lobs.Package, version=lobs.Version(1, 0, 0)):
       """A composed application with library dependencies."""

       # Inner library definition
       utility_lib = lobs.cpp.project.SimpleLibrary(
           source_files=[Path(__file__).with_name("src") / "utils.cpp"],
           public_includes=[Path(__file__).with_name("include")],
           cxx_standard=23,
       )

       # Application that links to the library
       app = lobs.cpp.project.SimpleManagedApplication(
           source_files=[Path(__file__).with_name("src") / "main.cpp"],
           linked_libraries=[UtilityLib],  # Reference by class type
       )


**Export Results:**

.. code-block:: bash

   python composed.py export cmake

Outputs:

.. code-block:: text

   ./generated/
   ├── CMakeLists.txt                          # Top-level project config
   ├── utility_lib/CMakeLists.txt              # Library build file  
   └── myapp/CMakeLists.txt                    # Application build file


Best Practices
--------------

- **Single Responsibility**: Each package represents one logical unit (library or application)
- **Explicit Paths**: Use ``Path(__file__)`` for robust path handling
- **Version Pinning**: Declare versions to ensure consistent builds
- **Clear Descriptions**: Provide meaningful descriptions for better discoverability
